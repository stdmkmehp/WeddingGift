## 修改线上 code_plaintext 密钥的方案评估
- 背景：已上线某 credential_mode=code 的礼品 code_plaintext 填错，需按 external_ref（如 GI003）修正。
- 结论：可行，但不能纯 shell+sqlite3 改库——`gift_item.code_ciphertext` 是 AES-256-GCM 密文（app.key → HKDF `wedding/gift-code-v1`），必须复用应用内 `cryptox`。
- 推荐形态：单二进制新增子命令（如 `wedding gift fix-code --ref GI003`）+ `ops/fix-gift-code.sh` 薄封装（先 `backup create`，再 `docker compose run --rm -T app ...`，对齐 append-data.sh）。
- 关键事实：`gift.RevealCode` 无缓存、每请求直查 DB 解密，UPDATE 后立即生效无需停服；WAL+busy_timeout 5000 在线安全；需重新构建发布镜像。
- 纪律：明文从 stdin/隐藏输入读（禁命令行参数，防 shell history/ps 泄露）；仅允许 code 模式、external_ref 必须存在、写后读回解密比对；不打印明文；属「上线后纯追加」约定的有意例外（纠错），需补 runbook 章节。
- 停机性确认（用户追问）：全程零停机——`compose run --rm` 一次性旁路容器与运行中服务并存；UPDATE 立即生效（RevealCode 无缓存直读库）；新子命令虽需重建/load 镜像，但 load 后可暂不重启运行容器（旧容器继续服务不受影响），留待下次正常发布切换。

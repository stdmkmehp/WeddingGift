## ops 脚本族：镜像离线发布 + 停起服拆分 + reset/restore 仅操作 DB

- 背景：正式机构建机无法直达 Go 模块源/镜像源（Dockerfile 构建阶段需 `go mod download` + 拉取 `golang:1.27-alpine`），镜像一律改为**开发机构建、正式机 load** 的离线发布流程。
- 新增脚本（均 `sh` + `set -eu`，与既有风格一致）：
  - `ops/build-image.sh`（开发机）：注入 git 版本信息 → `docker compose build` → `docker save wedding-app:latest | gzip` 到 `dist/wedding-app-<version>-<commit>-<UTC时间戳>.tar.gz`（`dist/` 已在 .gitignore）；输出 sha256（兼容 macOS `shasum -a 256`）与 scp/load 下一步命令。
  - `ops/load-image.sh`（正式机）：参数指定或默认取 `dist/` 下最新压缩包；体检（存在/非空/gzip 魔数 `1f8b` 用 `od` 判断/`gzip -t`）；`gzip -dc | docker load` 流式加载不落中间 tar；核对 `wedding-app:latest` 存在。
  - `ops/stop-app.sh`：容器运行才 stop 并等待退出，已停止/不存在幂等跳过。
  - `ops/start-app.sh`：运行中幂等跳过；容器不存在时先核对本地镜像存在（缺失则报错引导 load-image.sh，避免正式机触发 compose build 必失败）；`up -d` 后等待 healthy。
- 改造 `ops/reset-db.sh` / `ops/restore-db.sh`：**仅操作数据库，不停起服**——前置检查容器 `State.Running`，运行中直接报错退出引导 `ops/stop-app.sh`；restore 的 rollback 不再 `up -d`（失败回滚只恢复文件状态，起服由操作者显式执行）；restore 原「4/4 启动等健康」改为「4/4 输出脱敏统计」（status 失败也触发 rollback）；结尾均提示 `ops/start-app.sh`。
- 文档：`docs/06-m6-runbook.md` §2.5（构建并传输镜像三步骤）、§2.8、§5 发布序列（stop-app.sh → migrate → start-app.sh）、§6.2/§6.3（停服前置）、§7 回滚表、§10 变更记录 v2.3 同步更新。
- 验证：6 个脚本 `sh -n` 语法全过；`ops/test.sh` 秘密扫描不覆盖 shell 脚本内容，无影响。
